# cmd/server

В данной директории будет содержаться код Сервера, который скомпилируется в бинарное приложение.

## Аудит запросов

Аудит включается отдельно для каждого приёмника:

| Флаг | Переменная окружения | Назначение |
| --- | --- | --- |
| `--audit-file` | `AUDIT_FILE` | Путь к файлу аудита |
| `--audit-url` | `AUDIT_URL` | Полный HTTP/HTTPS URL приёмника |

Переменные окружения имеют приоритет над флагами. Пустое значение отключает
соответствующий приёмник. Если оба параметра пустые, аудит отключён.

```bash
go run ./cmd/server --audit-file audit.jsonl --audit-url http://localhost:9090/audit
AUDIT_FILE=audit.jsonl AUDIT_URL=http://localhost:9090/audit go run ./cmd/server
```

После успешного обновления через `/update/:metricType/:metricName/:metricValue`,
`/update` или `/updates` сервер синхронно отправляет одно событие всем настроенным
приёмникам перед ответом клиенту. JSON-маршруты также принимают завершающий `/`.
Для одиночного JSON-обновления событие создаётся после подготовки ответа.
Запросы чтения, пустые пакеты и запросы, завершившиеся ошибкой, не создают событий.

```json
{"ts":12345678,"metrics":["Alloc","Frees"],"ip_address":"192.168.0.42"}
```

`ts` — Unix timestamp в секундах. Имена метрик сохраняют порядок и повторения
в запросе. `ip_address` — IP адрес соединения без порта; заголовки прокси не
учитываются.

Файловый приёмник дописывает JSON на отдельной строке, создавая новый файл с
правами `0600`. HTTP-приёмник отправляет POST с `Content-Type: application/json`,
тайм-аутом 1 секунда и принимает только ответы `2xx`, без переходов по редиректам.

Некорректный URL или невозможность открыть файл останавливают запуск сервера.
Ошибки доставки во время работы записываются в обычный лог и не меняют успешный
ответ клиенту. Повторные отправки автоматически не выполняются.
